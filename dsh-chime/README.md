# dsh-chime · 响铃提醒

> **只想用、不想读代码** → [CHEATSHEET.md](CHEATSHEET.md)（一页速查：怎么调音色、传自己的铃声、关升级、出问题看哪里）
> **要改代码** → [HANDOFF.md](HANDOFF.md)（交接文档：铁律、代码地图、验证命令、待办与踩坑记录）

后台干活时你在别的窗口里忙，不用一直盯着屏幕——**活干完了响一声舒缓的，需要你出面时响急促的。**

- 🔔 **需要你协助**（急促：三轮连击）— agent 问你问题、计划等你批准、卡住了、出错了
- ✅ **工作完成**（舒缓：C6-E6-G6 上行琶音）— 这一轮正常干完
- 补充音色：**警醒**（下降小二度，出错）、**单声叮**（轻提示）

围绕这两声铃，另外还有四件事：

| 功能 | 一句话 |
|---|---|
| **真·实时** | 宿主到浏览器走 SSE 长连接（实测 1 ms），后台标签页不再被浏览器节流拖到一分钟 |
| **自定义铃声** | 上传自己的 wav/mp3，在设置页里选中即可（存在 `$DSH_HOME\dsh-chime\sounds\`，重装不丢） |
| **响过没人理就升级** | 只对「需协助」类：首次延迟后追着重响，音量逐次抬高，最多 3 次；你一回到页面立刻停 |
| **标题闪烁 / 桌面通知** | 只在页面不可见时闪标题（带待看条数），切回即恢复；桌面通知可点一下回到页面 |

## 触发规则

判定全部在**宿主端**做（浏览器只看得到你打开的那个会话，宿主看得到全部）。

| 时机 | 会话事件 | 判据 | 通知 | 铃声 |
|---|---|---|---|---|
| 干完了 | `turn/end` | `reason.kind === 'completed'` | 活干完了 | 舒缓 |
| 问你问题 | `tool/call` | 工具名 = `ask_user_question` | 有事情问你 | 急促 |
| 计划待批 | `tool/call` | 工具名 = `exit_plan_mode` | 计划待你批准 | 急促 |
| 卡住了 | `turn/end` | `reason.kind === 'blocked'` | 卡住了，等你发话 | 急促 |
| 出错了 | `turn/end` | `reason.kind === 'error'` | 出错了，需要你看一眼 | 急促 |
| 你自己按的停 / 被中断 / 超长 | `turn/end` | `aborted` / `interrupted` / `max-tokens` / `forked` | — | 不响 |

两条降噪规则：

1. **同一轮里问过就不再响第二次**：agent 提问后这一轮往往以非 completed 收尾，若两边都响会变成连环铃。
2. **子 agent 会话默认不单独响铃**：子任务通常由主会话收口，每个子 agent 都响会变成噪音（宿主端 `config.notifySubagentSessions: true` 可打开）。

## 安装

插件目录（本机）：`<plugin-directory>`

在 profile 的 `package.json` 里 link：

```json
{
  "dependencies": {
    "dsh-chime": "link:<plugin-directory>"
  },
  "dsh": {
    "profile": {
      "bundles": [ "...", "dsh-chime" ]
    }
  }
}
```

然后在该 profile 目录执行 `pnpm install`（link 依赖也要走一次安装，profile 的 node_modules 里才会出现 `dsh-chime` 软链）。加载与否由 bundle patch 的 `cordis.patch.yml` 决定（`- insert: [{ id: dsh-chime, name: dsh-chime }]`），纯 insert 可热挂载。

## 设置

「设置 → 响铃」里有：总开关、解锁音频、音量、完成/需协助各自的音色、静音时段（支持跨零点如 23:00–07:00）、**响过没人理就升级**（开关 + 首次延迟秒数；需协助响铃后没人回来就按 +45 秒节奏最多再响 3 次、音量递增，一回到页面或有任何操作立刻停止）、标签页标题闪烁、桌面通知、最近通知记录，以及「让宿主发一条测试通知」——它走完整链路（宿主入队 → 网页轮询 → 响铃），是验证安装是否成功的最快方式。

设置存在浏览器 `localStorage`（`dsh-chime.settings.v1`），不落宿主：宿主崩溃或配置写坏时不会连带把插件卡死。

## 为什么要有「解锁音频」

浏览器规定：页面在收到一次真实交互（点击/按键）之前不允许自动播放声音。所以：

- 首次装好后，**点一下页面任意位置**（或设置页里的「解锁并加载」）即可；
- 设置页会显示当前音频状态（已解锁 / 未解锁）；
- 页面加载时插件会预热解码全部铃声，第一次响铃没有延迟。

## 架构

```
   agent 干活 ──► 会话事件流
                     │  ctx.on('session/event')   ← 宿主内部同步回调，延迟 <1ms
                     ▼
   ┌───────────────────────────────┐        ┌──────────────────────────┐
   │ 宿主半边 lib/index.js          │        │ 浏览器半边 lib/client.js  │
   │ · 判定「值不值得响铃」          │  SSE   │ · EventSource 长连接订阅  │
   │ · 通知队列（seq 单调递增）      │───────►│ · Web Audio 播放 WAV      │
   │ · /dsh-chime/stream 实时推送    │ 推送    │ · 设置页「响铃」          │
   │ · /dsh-chime/poll 增量拉取(兜底)│◄──────►│ · 静音时段 / 音量档位     │
   │ · /dsh-chime/sounds/*.wav      │  HTTP  │ · /status 诊断面板        │
   │ · /dsh-chime/test 自塞一条      │        │ · 断线补拉 / 去重         │
   │ · /dsh-chime/status 诊断        │        │                          │
   └───────────────────────────────┘        └──────────────────────────┘
```

**两段延迟，分开看：**

| 段 | 机制 | 延迟 |
|---|---|---|
| agent 干活 → 宿主判定 | `ctx.on('session/event')` 事件驱动（插件跑在 DSH 主进程里，不是外部脚本） | < 1 ms |
| 宿主判定 → 浏览器响铃 | SSE 长连接推送（`/dsh-chime/stream`） | 实测 **1 ms**（真 HTTP 测试量出来的） |

改造成 SSE 之前，第二段是 2 秒轮询、**后台标签页还要被浏览器节流到分钟级**——「工作完成」这种提示最慢要等一分钟才响。现在推送不受节流影响。轮询没有删掉：它降级成 `20 s` 一轮的兜底，并且负责**断线补拉**（每次 SSE 连上/重连，客户端都拿本地游标补一次 `/poll`，把断线期间漏掉的通知捞回来）。

关键逻辑都是**可离线验证的纯函数**——判定规则（`lib/rules.js` 的 `decide()`）、批次决策（`decideBatch`）、升级链调度与取消（`createEscalation`）、标题闪烁与桌面通知（`createTitleFlash` / `createDesktopNotifier`）——测试直接从 `lib/client.js` 源码里把它们抽出来执行，测的就是线上那份逻辑。**`npm test` 105 项全绿**，不用装上以后靠耳朵验证。

### 踩过的坑（都写进测试钉住了）

- **prefix 路由不能带尾斜杠**：Web 服务器按 `${prefix}/` 比较，注册 `/dsh-chime/sounds/` 会让 `/dsh-chime/sounds/complete.wav` 永远匹配不上（表现为铃声 404）。现在注册的是 `/dsh-chime` 并在 handler 内部二次分派，注册器还会替调用方剥掉尾斜杠。
- **客户端 bundle 的 `__ModuleLoader__.load({ id })` 必须是包名**（`dsh-chime`），不是 patch 里的行 id；写错会报 `loaded without registering`，整条客户端行不挂载。
- **一批通知一起到达时不能逐条响**：页面刚从后台回来、或断线重连时队列会积压多条，逐条播放 + 冷却会把后面几条**静默吃掉**（游标已推进，等于永久丢失），用户听到的表现就是「只响了一声，而且未必是最重要的那条」。现在只挑**最急的一条**响（`assist`/`alert` > 完成），其余记成「已合并」，一条都不丢。
- **排序比较器必须返回 `-1/0/1`**：直接写成「时间戳相减」会得到浮点差值，而排序只认符号，`0.8` 判成相等 → 顺序退回数组顺序（真踩过：最新的那条反而没响）。
- **SSE 的写帧必须对着订阅记录，不是客户端 id**：`sseSend(id, payload)` 写成 `id.socket.write(...)` 时，`id` 是字符串，`id.socket` 是 `undefined` → 每帧都写失败、连接被立刻断开。假 req/res 的测试抓不到它（假对象的 `write` 永远"成功"），所以另写了 `tests/sse-http.test.mjs`：把真实 handler 挂到真实 http 服务器、用真实 fetch 读流。
- **SSE 心跳要把长连接收干净**：心跳 `setInterval` 如果只在插件卸载时清、不 end 掉已连上的 socket，热重载后旧页面会挂在一条没人写的连接上；测试里还暴露过「定时器把 Node 测试进程挂住」——所以 `host.test.mjs` 结束时统一跑所有 `ctx.effect` 清理器。

### 音量档位

滑杆是总音量；「完成时」的铃声再乘 0.8（舒缓音不该吓人），「需协助时」用满音量。两条都随同一个滑杆缩放，避免出现「急的那条反而更轻」。

为什么不是宿主直接放声音：宿主进程在后台跑，声音必须由你坐着的那个浏览器发。宿主只当裁判。

HTTP 路由（同一插件命名空间，不碰宿主其它路由）：

- `GET /dsh-chime/stream` → **SSE 长连接**：连上先发一帧 `hello`（带当前水位，供客户端判断要不要补拉），之后每条通知即刻推下去；每 25 秒发一次注释行做心跳。断开时宿主立刻回收（不留下没人写的连接）。
- `GET /dsh-chime/poll?since=<seq>` → `{ items: [...], lastSeq }` 增量拉取：现在是**兜底与断线补拉**，不是主通道。
- `GET|POST|DELETE /dsh-chime/sounds/custom` → 自定义铃声：列出 / 上传（JSON + base64）/ 删除。
- `GET /dsh-chime/sounds/<name>` → 内置或自定义铃声文件（只按「内置白名单」与「扫描出来的真实文件」取，请求里的路径绝不参与拼接）；
- `GET /dsh-chime/test?kind=<name>` → 自己塞一条测试通知，验证全链路；
- `GET /dsh-chime/status` → 诊断口：活着多久、监听到哪些事件（按 `turn/end:<reason>`、`tool/call:<name>` 分类计数）、入队与去重次数、队列现状、**在线 SSE 页面数**、自定义铃声数量与目录。

设置页里有「看诊断信息」按钮直接读这个口；命令行也行：

```powershell
curl "http://127.0.0.1:19387/dsh-chime/status"
```

事件年龄超过 120 秒、或队列里超过 5 分钟的通知不下发：断线重连、宿主重启后不会补响一耳朵旧铃。（120 秒这条线最初是 8 秒，实测太紧——页面在后台时浏览器会把定时器节流到分钟级，切回来时提醒已经掉进死区、被静默忽略，表现就是「怎么没响」。）

## 自定义铃声

设置 → 响铃 → **自定义铃声**：上传你的 wav / mp3 / ogg / m4a / flac / webm（单个 ≤ 8 MiB），传完就能在「完成时 / 需协助时」的下拉里选它；右侧下拉可以删除。

- **存哪儿**：`$DSH_HOME\dsh-chime\sounds\`。刻意**不放进插件目录**——那里是 git 仓库，塞二进制会脏；而且这样重装、升级、甚至删掉插件目录重拉，你上传的铃声都还在。
- **文件名收敛**：只保留中日韩字母数字与 `-` `_`，其余折成 `-`，长度截到 48；落盘文件名由收敛后的名字拼扩展名。**请求里的路径永远不参与拼接**，所以 `../` 之类进不来（测试里有专门一条钉这个）。
- **格式判定**：先看文件名后缀，认不出就看文件头（RIFF/WAVE、OggS、fLaC、ID3 或 MPEG frame sync、ftyp、EBML），两样都认不出就拒绝并告诉你接受哪些——不留「存下来了但放不出来」的文件。
- **为什么用 JSON + base64 而不是 multipart**：8 MiB 以内的膨胀可以接受，换来宿主端零依赖（不用引入任何 body 解析库）。

## 音频资源

`sounds/*.wav` 由 `sounds/synth_sounds.py` 纯合成生成（numpy 加法合成，无音频库依赖），22050 Hz 单声道 16-bit：

| 文件 | 时长 | 音色 |
|---|---|---|
| `complete.wav` | 2.60 s | C6-E6-G6 上行琶音，长衰减，舒缓 |
| `assist.wav` | 0.95 s | A5-E6 三轮连击，短衰减，急促 |
| `alert.wav` | 1.30 s | E5–♭E5 下降小二度 ×2，警醒 |
| `blip.wav` | 0.55 s | 单声短「叮」，轻提示 |

改音色：编辑 `synth_sounds.py` 里的音符表重新生成，或用 `python sounds/check_sounds.py` 打印包络/音高自检（确认乐句真的成型，而不是一串噪声）。

### 三条互相独立的验证路径

出问题时最难的是分清「文件坏了 / 浏览器放不出来 / DSH 没集成好」。这三条分别证明一件事：

| 命令 / 文件 | 证明什么 | 依赖 |
|---|---|---|
| `python sounds/check_sounds.py` | WAV 字节是对的：包络有音节、音高符合设计、无削波 | 只依赖 numpy |
| `node tests/render-audio.mjs` | **真实浏览器引擎**能解码并播出信号：headless Edge + CDP，用 AnalyserNode 量出播放期峰值 | 本机 Edge |
| `sounds/preview.html`（双击打开） | 你的**音箱和系统音量**没问题（人耳闭环） | 任意浏览器 |

`render-audio.mjs` 的输出（本机实测）：四段音频解码时长 2600/950/1300/550 ms 与设计一致，`AudioContext=running`，播放 assist 音时峰值 **0.799**、57 帧里 52 帧有信号。它证明的是「产生了音频信号」，不证明「扬声器响了」——headless 不接音箱，后者只能由 `preview.html` 给人听。

生成/更新试听页：`python sounds/make_preview.py`（把四个 WAV 以 base64 内嵌成单文件 `preview.html`，约 316 KiB）。

## 已知边界

- 只在 Web GUI 打开着（哪怕是后台标签页）时能响；浏览器完全关闭就收不到铃声（宿主端不落盘通知）。
- 后台标签页的定时器会被浏览器节流（Chromium 约 1 分钟一次），所以「需要协助」可能延迟十几秒；要彻底实时得把轮询换成宿主推送（SSE）。
- 声音响在**打开着页面的那台机器**上；多设备同时开着会同时响。
- 权限审批（approval）不在触发列表里：只有宿主实际发出权限审批请求时才会触发此类提醒；如果 profile 禁用了审批，就不会产生该事件。
- 通知入队是内存态，DSH 重启即清空（这正是想要的：重启后不该补响历史铃）。
- 自定义铃声单个不超过 **8 MiB**（JSON + base64 上传的刻意上限）；支持的格式：wav / mp3 / ogg / m4a（ftyp 族）/ flac / webm（EBML 族），认不出的会在上传时拒绝并说明。
- 「响过没人理就升级」只追**需协助类**（含测试通知），完成音不追；最多 3 次重响，音量逐次 ×1.3 / ×1.6 / ×1.9 但封顶满音量 1.0——所以滑杆本来就开在 100% 时，升级体现为「再响几次」而不是「更响」。
- 改了宿主半边（`lib/index.js`）后需要**重启 DSH 进程**才生效——HMR 只重载它观察到的模块变更，link 插件的源码目录不在它的监视范围内；浏览器半边（`lib/client.js`）改动则由客户端 HMR 或页面刷新接管。
