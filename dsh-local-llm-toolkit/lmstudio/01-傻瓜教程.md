### 路线 B：镜像下载（国内稳，推荐）

双击运行我写好的脚本：

> ✅ **实测：三个模型全部下完只用了约 3 分 40 秒**（99.6 / 105.8 / 33.3 MB/s）。hf-mirror 速度非常好，13GB 完全不是问题。

**手动下载也可以**，规则是「作者 / 仓库名 / 文件名」三层目录，放到 `settings.json` 里 `downloadsFolder` 指定的位置（**本机已改到 E 盘**）：

```

```

> ⚠️ **模型目录千万别留在 C 盘。** LM Studio 装在哪个盘，跟模型存哪**没有关系**——模型目录由 `settings.json` 里的 `downloadsFolder` 决定，而它**默认永远是 C 盘用户目录**。

> **改法**：LM Studio 设置 → My Models → 把目录换到空间大的盘（改完 `settings.json` 的 `downloadsFolder` 会跟着变）。
> **搬家顺序**（必须遵守）：先关掉 LM Studio → 移动模型文件 → 改配置 → 再启动。**程序运行中改配置会被它退出时覆写掉。**

对应本次三个模型的完整地址（把 `resolve/main` 当直链用）：

```

https://hf-mirror.com/mradermacher/Hunyuan-MT-7B-GGUF/resolve/main/Hunyuan-MT-7B.Q4_K_M.gguf
```

## 3. 加载参数：照抄这张表

在 **My Models** 里找到模型 → 点模型卡片右侧的 **齿轮/配置**（或先点模型再点右下角设置），按下面填：

| 参数（界面上的名字） | 填什么 | 为什么 |
|---|---|---|
| **GPU Offload**（GPU 卸载层数） | **拉满 / 最大值**（默认 `max`，填 999 也行） | 7B Q4 只有 4.36GB，8GB 显存放得下全部 28 层，全放 GPU 才快 |
| **Context Length**（上下文长度） | **8192** 起步；要翻译长文档改 **16384** | 你的默认值已经就是 8192。16K 只多占约 0.25GB 显存 |
| **Flash Attention** | **开（ON）** | 省显存、提速 |
| **K Cache Quantization / V Cache** | **Q8_0** | 上下文显存减半，几乎不掉质量 |
| **CPU Threads** | **8** | i7-13650HX 有 20 线程，GPU 是主力，CPU 留一半给系统 |
| **Batch / uBatch** | 默认 **512 / 512** | 不用改 |
| **Keep in RAM / mmap** | 默认 | 不用改 |
| **Temperature** | 总结/翻译 **0.3**；写代码 **0.2**；闲聊 0.7 | 粗活要稳，不要发挥 |

### 显存预算（为什么这套参数能跑）

```
模型权重  Q4_K_M              4.36 GB
KV cache  8192 上下文 Q8      0.25 GB
计算缓冲                      约 0.8 GB
Windows 桌面/浏览器（实测）  约 1.16 GB
────────────────────────────────────────
总计                          约 6.6 GB  /  物理 8 GB   ✅ 还有约 1.4GB 余量
```

**注意事项**：浏览器（Chrome/Edge 的硬件加速）、剪映、游戏、Wallpaper Engine 都会抢显存。一旦加载时报 `out of memory` / 显存不足：
1. 先关浏览器标签页；2. 把上下文从 16384 降到 8192 或 4096；3. 还不行就把 GPU Offload 降到 20 层（剩下的走 CPU，会慢 3–5 倍，但能跑）。

参考速度（4060 Laptop，7B Q4_K_M 全量 GPU）：**生成约 30–50 token/s**，读一段 2000 字的英文再翻成中文，大约 10–20 秒。

### 实测结果（我在你这台机器上真加载跑过，不是估的）

| 模型 | 上下文 | Parallel | 实测显存占用 | 生成速度 | 翻译一段 113 token 英文的耗时 |
|---|---|---|---|---|---|
| Qwen2.5-7B-Instruct Q4_K_M | 8192 | 4（默认） | 5353 MiB（剩 2605） | **33.9 token/s** | 2.5 秒 |
| Hunyuan-MT-7B Q4_K_M | 8192 | 4（默认） | 6734 MiB（**只剩 1224**） | 30–38 token/s | 2.7–2.9 秒 |

**两个必须知道的结论**：
1. **Hunyuan-MT-7B 比 Qwen2.5-7B 多吃约 1.4GB 显存**（同样的上下文和并发设置）。加载它之前一定先关浏览器，并且把 **Parallel 从默认 4 改成 1** —— 你是一个人用，根本不需要并发，改完能省下可观的 KV cache。
2. 默认 `Parallel = 4` 的意思是把 KV cache 乘以 4 份。**单用户场景一律设成 1**，省显存或者换更长的上下文，两者都更划算。

实测译文质量（同一段英文）：Qwen2.5-7B 更简洁书面，Hunyuan-MT-7B 更忠实但略啰嗦（会自行加括号补充）。**翻译任务两个都能用，Hunyuan-MT 略优；总结/问答/编程用 Qwen2.5。**

## 4. 打开本地服务器（让脚本/其他软件能调用）

两种开法，任选：

**界面开**：左侧 **Developer（开发者）** 图标 → 顶部 **Status** 开关打开 → 端口默认 `1234`。

**命令行开**（更省事）：
```powershell
& "$env:USERPROFILE\.lmstudio\bin\lms.exe" server start
& "$env:USERPROFILE\.lmstudio\bin\lms.exe" server status
```

**验证是否成功**：
```powershell
curl.exe http://127.0.0.1:1234/v1/models
```
能返回模型列表 JSON 就说明通了。这是一个**完全兼容 OpenAI 格式**的接口，所以任何支持自定义 API 的软件（Obsidian 插件、沉浸式翻译、Continue、Cherry Studio…）都能接：

```
接口地址(Base URL): http://127.0.0.1:1234/v1
API Key:           随便填（如 lm-studio）
模型名:            用 /v1/models 返回的那个 id
```

> ⚠️ 别搞混：日志和进程里那个 **41343 端口**是 LM Studio 自己内部通信用（Electron 主进程 ↔ 界面）的，**不是**给你调 API 的，别拿它对接。给外部用的一定是 1234。

### 用命令行加载/卸载模型（参数可复现，推荐）

```powershell
$lms = "$env:USERPROFILE\.lmstudio\bin\lms.exe"
& $lms load qwen2.5-7b-instruct --gpu max -c 8192 -y --identifier qwen25   # 全量 GPU + 8K 上下文
& $lms ps                                                                   # 看当前加载了什么、占多少显存
& $lms unload qwen25                                                        # 卸载，立刻释放显存
```

**踩过的坑**：
- 模型名必须用 `lms ls` 里列出的那个 key（如 `qwen2.5-7b-instruct`）。写成完整路径 `lmstudio-community/qwen2.5-7b-instruct` 会报 `Model not found`。
- `qwen2.5-7b-instruct` 会**同时匹配到 coder 版**（提示 `2 models match ... Loading the first one`），它会取第一个。想绝对精确就加 `--identifier`，装完用 `lms ps` 核对加载的到底是哪个。

## 5. 日常工作流：本地干粗活，云端干精活

核心逻辑：**本地模型不要钱但不够聪明，云端 API 很聪明但按 token 收费**。所以让本地模型吃掉 80% 的 token，云端只处理最后的 20%。

```
PDF/扫描件
   │
   ├─〔本地·免费〕文本提取 / OCR   ← 纯工具，不占显存
   │
   ├─〔本地·免费〕Qwen2.5-7B  初翻：英→中，逐段直译，不要润色
   │                              或  长文分块摘要（每块 2000 字）
   │
   ├─〔本地·免费〕Qwen2.5-7B  合并分段摘要，输出结构化的中文大纲
   │
   └─〔云端·少量 token〕把"初翻稿/粗摘要"发给强模型，只做：
         · 术语统一、语气润色、书面化
         · 深度推理、批判性分析、生成最终报告
```

> ⚠️ **"本地翻译省钱"这个说法是错的**（实测数据见文末**附录 A**）。
> 翻译的贵在**输出**，而输出量是固定的——本地译一遍、云端再全量精修一遍，云端成本**反而更高**。
> 本地流水线真正省钱的姿势是：**云端只碰那必须碰的一小撮**（本次实测只精修了全书的 1.3%，花了 ¥0.014）。
> 本地部署买到的是**隐私、可重复、不受限流**，不是省 API 钱。

**本地"初翻"提示词模板**（直接复制）：
```
你是翻译引擎。把下面的英文逐段直译成中文，保留段落结构，
不要意译、不要加解释、不要总结。遇到专有名词保留英文原文加括号注释。

<原文>
{这里粘贴原文}
</原文>
```

**本地"粗摘要"提示词模板**：
```
把下面的文档压缩成不超过 300 字的中文要点清单，
只保留事实、数字、结论。分点输出。

<文档>
{这里粘贴文档}
</文档>
```

**云端"精修"提示词模板**（发给强模型，token 消耗很小）：
```
下面是一份机器初翻的中文稿，请：1) 修正翻译腔，改成通顺的书面中文；
2) 统一术语；3) 保持所有数字和事实不变；4) 分节输出。
不要添加原文没有的内容。

<初稿>
{粘贴本地产出的初稿}
</初稿>
```

```powershell
powershell -ExecutionPolicy Bypass -File "E:\0001bendiAI\LMStudio-部署\04-收集日志.ps1"
```
它会把日志、配置（**自动抹掉 token 密钥**）、硬件信息、模型列表打成一个 zip，放在桌面。你把 zip 发我即可。

### 关于那条一直刷的登录报错

```
[AppAuthenticationProvider] Failed to verify authentication: Error: Invalid Key ID
[LMSInternal][LMSAuthenticator][Endpoint=authenticate] Error in RPC handler: Error: Authentication timed out. (toastIgnore)
```
（第一条每 16 秒刷一次，第二条是你的登录会话彻底超时了 —— 两条都不影响本地模型跑）
- **不会影响**本地模型运行，可以无视。
- 想彻底消掉：LM Studio 左下角 **设置/账号** → 退出登录（Log out）→ 重新登录；或者跑 `lms logout` 后 `lms login`。

# 附录 A · 成本真相：本地部署到底省不省钱（实测数据）

> 这一节全部是**实测数字**，不是估算。目的是纠正一个流传很广的说法：**"本地部署能省 API 钱"**。

## A.1 实测基准

样本：286 页英文专著（Steven G. Krantz《The Survival of a Mathematician》，63 万英文字符），用本书的文档流水线跑完全书。
token 数用真 tokenizer（tiktoken）数出来：

| tokenizer | 输入（英文原文） | 输出（中文译稿） | 合计 |
|---|---|---|---|
| cl100k（GPT-4 系） | 132,983 | 219,742 | 352,725 |
| o200k（GPT-4o/5 系） | **132,596** | **139,684** | **272,280** |

⚠️ **中文输出对 tokenizer 极度敏感**：同一份 20.6 万字符的中文译稿，cl100k 要 219,742 tokens，o200k 只要 139,684，**差 57%**。选对模型比砍价更管用。

## A.2 云端全译这本书要多少钱

以 DeepSeek-V4.1-Flash（模型名 `deepseek-flash`）官方原价为例，单位：元 / 百万 tokens。

| 计费项 | 空闲时段 | 高峰时段 |
|---|---|---|
| 输入（缓存**命中**） | ¥0.02 | ¥0.04 |
| 输入（缓存**未命中**） | ¥1 | ¥2 |
| 输出 | ¥4 | ¥8 |

**高峰时段**仅指：周一至周五 9:00–12:00、14:00–18:00（北京时间，不含法定节假日）。**其余时间一律五折**，包括周末和节假日全天。

**全书直译成本**：

| 方案 | 高峰 | 空闲 |
|---|---|---|
| 程序化直译（逐块发送，无历史累积） | **¥1.38** | **¥0.69** |
| 在对话里逐章翻译（历史走缓存命中） | ¥1.88 | ¥0.94 |

> **成本结构：输出占了总价的 81%**（¥1.12 / ¥1.38）。所以省钱的真杠杆是**砍输出**，不是砍输入。

## A.3 本地跑这本书的账

| 项目 | 实测值 |
|---|---|
| 耗时 | 48.4 分钟（315 块，平均 38.9 token/s） |
| 功耗 | GPU 84W，整机约 150W |
| 耗电 | 约 0.12 度 |
| **电费** | **≈ ¥0.07** |

**本地是云端的约 1/10（按空闲时段价）。但绝对差值：一本书省 7 毛钱。**

## A.4 两个必须纠正的误解

### ❌ 误解一：本地翻译 + 云端精修 = 便宜

| 方案 | 云端输入 | 云端输出 | 空闲价 |
|---|---|---|---|
| 直接云端翻译 | 132.6K | 139.7K | ¥0.69 |
| 本地译完 → 云端**全量**精修（只发中文初稿） | 139.7K | 139.7K | ¥0.70 |
| 本地译完 → 云端**全量**精修（带原文对照，这才靠谱） | 272.3K | 139.7K | **¥0.96** ⬆️ |

**因为输出的钱省不掉**：本地译一遍、云端再写一遍 = 输出翻倍。带原文对照做精修甚至比直译更贵。

### ❌ 误解二：在对话里翻会比 API 贵好几倍

有了前缀缓存（命中价是未命中的 1/50），对话式只比程序化贵 **1.36 倍**。

## A.5 那本地部署到底值不值

| 方案 | 花钱 | 时间 |
|---|---|---|
| 全本地（Hunyuan-MT-7B） | ¥0.07（电费） | 48 分钟 GPU 满载 |
| 全云端（V4.1-Flash 空闲时段） | ¥0.69 | 几分钟 |
| 本地译 + 云端只精修问题块 | ≈ ¥0.09 | 48 分钟 + 人工复核 |

> 更扎心的账：这次为了建流水线 + 翻完全书 + 全套质检，光**和 DSH 对话编排**就花了约 **¥0.5**（估算）。
> **省下 7 毛，花掉 5 毛和两个多小时**——这就是"省钱"不能当本地部署理由的原因。

**只翻一本书，本地部署在钱上是赔本买卖。它真正买到的是三样钱买不到的东西：**

1. **隐私**——63 万字符的原文，一个字没出过本机；
2. **可重复**——断点续传、无限次重跑、改提示词再跑一遍，都是 0 成本；
3. **不受限流约束**——半夜想连跑 20 本书，本地随时开工，不占并发额度。

## A.6 所以正确的用法是

- **翻译 / 摘要这类"输出量大"的活**：本地干粗活，**云端只精修出问题的那一小撮**（实测只精修了全书的 1.3%，花 ¥0.014）。
- **别让云端做全量精修**——那比直译还贵。
- **批量任务排到夜里 / 周末**，云端自动五折。
- **云端翻译时关掉思考模式**——翻译不需要推理链，能砍掉大量输出 token。

> 一句话：**本地部署买的是隐私和自由度，不是省钱。**
> 真想在钱上划算，正确姿势是"**本地干完 98.7%，云端只碰 1.3%**"。
